# ПП 1875 — AI Procurement Copilot

Локальный классификатор наименований товаров по приложениям Постановления Правительства РФ от 23.12.2024 № 1875. Система возвращает позицию приложения, код ОКПД2, национальный режим, квоту для 223-ФЗ, уверенность модели, альтернативы и ссылку на источник.

## Что реализовано

- одиночная классификация и пакеты до 100 товаров;
- семантические эмбеддинги на локальной мультиязычной модели `paraphrase-multilingual-MiniLM-L12-v2`;
- PostgreSQL + pgvector, HNSW-индекс и косинусная близость;
- точное совпадение по коду ОКПД2, если код уже указан в запросе;
- Celery + Redis для фоновой обработки без блокировки интерфейса;
- 893 позиции справочника: приложение № 1 — 151, № 2 — 465, № 3 — 277;
- импорт CSV/TXT и экспорт результатов CSV с UTF-8 BOM для Excel;
- асинхронная загрузка и извлечение текста из PDF/DOCX через Celery/Redis (PDF до 2 000 страниц, файл до 100 МБ);
- хранение заданий и извлечённого текста в PostgreSQL, просмотр статуса и выгрузка TXT;
- обновление всего справочника через JSON без пересборки и передеплоя;
- журнал классификаций, health/readiness checks, OpenAPI;
- адаптивный React-интерфейс, локальные шрифты, отсутствие внешних API при работе.

> Уверенность — эвристическое преобразование косинусного сходства и отрыва от альтернативы; оно не калибровалось как статистическая вероятность и не является юридической вероятностью. Итоговую применимость нормы и исключений должен проверять специалист по закупкам.

## Быстрый запуск через Docker

Подробная инструкция для первого запуска Windows 10/11 — от распаковки архива и создания `.env` до настройки пароля PostgreSQL, запуска Docker Compose и проверки классификатора — находится в отдельном файле **[START_HERE.md](START_HERE.md)**. Она рассчитана на пользователя, который впервые получил проект.

Краткая последовательность:

1. Распакуйте архив и откройте PowerShell в папке, где непосредственно лежит `docker-compose.yml`.
2. Создайте `.env` из `.env.example` и укажите собственные `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD`.
3. Убедитесь, что запущен Docker Desktop и доступны `docker compose version`.
4. Проверьте конфигурацию командой `docker compose config --quiet`.
5. Соберите и запустите проект: `docker compose up --build -d`.
6. Проверьте контейнеры: `docker compose ps -a`; затем проверьте API на `http://localhost:8000/api/v1/ready`.
7. Откройте интерфейс: **http://localhost:8080**.

Требования: Docker Engine 24+ и Docker Compose v2, не менее 4 ГБ свободной ОЗУ (рекомендуется 6–8 ГБ) и около 5 ГБ свободного диска. Интернет нужен при первой сборке для загрузки образов, библиотек и модели. Первый запуск может занять 10–20 минут в зависимости от сети и компьютера.

**Важно о пароле PostgreSQL:** при первом запуске на пустом Docker volume пользователь, база и пароль создаются из `.env` автоматически. Если volume уже существует, простая смена `POSTGRES_PASSWORD` в `.env` не изменит пароль роли в работающей базе. Для такого случая предназначен скрипт `fix-db-password.ps1`; подробности и безопасная последовательность приведены в [START_HERE.md](START_HERE.md) и [DB_PASSWORD_FIX.md](DB_PASSWORD_FIX.md). Не удаляйте volume командой `docker compose down -v`, если нужно сохранить данные.

Остановка: `docker compose down`. Запуск в фоне: `docker compose up --build -d`. Логи: `docker compose logs -f api worker`.

## Использование

### Один товар

Введите наименование, например «Сервер стоечный 2U» или «Товар с ОКПД2 28.22.14.121». Нажмите «Классифицировать». Раскройте «Альтернативы и метод», чтобы увидеть следующие ближайшие позиции.

### Список товаров

1. Перейдите на вкладку «Список до 100».
2. Вставьте по одному наименованию на строку или импортируйте TXT/CSV. Для CSV используется первый столбец; разделители `;` и Tab поддерживаются. Первая строка `Наименование` распознаётся как заголовок.
3. Нажмите «Обработать список». Запрос отправляется в очередь Celery, страница опрашивает статус задания.
4. Нажмите на строку результата для подробностей или скачайте весь результат в CSV.

### Разбор длинных PDF/DOCX без HTTP-таймаута

На вкладке «ПП1875 (импортозамещение)» можно загрузить PDF или DOCX до 100 МБ. API принимает файл, сохраняет его в общем Docker volume и немедленно отправляет задание Celery в Redis. Worker извлекает текст в отдельном процессе; PDF получает точное количество страниц, для DOCX показывается оценка объёма (формат DOCX не хранит фиксированную пагинацию). Лимит задачи Celery — 30 минут, API не удерживает HTTP-соединение во время извлечения. Результат доступен в интерфейсе и через `GET /api/v1/documents/{document_id}/text`.

Пример запроса:

```bash
curl -X POST http://localhost:8000/api/v1/documents \
  -F "file=@large-regulation.pdf"

# Используйте document_id из ответа:
curl http://localhost:8000/api/v1/documents/DOCUMENT_ID
curl -OJ http://localhost:8000/api/v1/documents/DOCUMENT_ID/text
```

PDF должен содержать текстовый слой. Сканированные изображения без OCR пока не распознаются — API возвращает явное сообщение об этом, а не пустой «успешный» результат.

### Обновление базы НПА без передеплоя

В разделе «Справочник» нажмите «Загрузить JSON» и выберите файл той же структуры, что `backend/data/catalog.json`. Можно также выполнить:

```bash
curl -X PUT http://localhost:8000/api/v1/catalog \
  -H "Content-Type: application/json" \
  --data-binary @backend/data/catalog.json
```

API валидирует документ, заранее создаёт эмбеддинги и атомарно заменяет данные в одной транзакции. Перезапуск не требуется. При сбое валидации старый справочник сохраняется. Поле `version` должно отражать вашу редакцию данных; `sha256` необязателен.

## Конфигурация

Все параметры задаются в `.env`; пример находится в `.env.example`.

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `POSTGRES_DB` | Имя базы | `procurement` |
| `POSTGRES_USER` | Пользователь БД | `procurement` |
| `POSTGRES_PASSWORD` | Собственный пароль БД | задаётся пользователем в `.env` |
| `MODEL_NAME` | Модель Sentence Transformers | `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` |
| `CORS_ORIGINS` | Разрешённые источники через запятую | `http://localhost:8080,http://127.0.0.1:8080` |
| `LOG_LEVEL` | Уровень логов | `INFO` |

`DATABASE_URL`, `REDIS_URL` и `CATALOG_PATH` Compose формирует автоматически. Размерность вектора модели — 384; при смене семейства модели с другой размерностью потребуется миграция схемы и полная переиндексация.

## Проверка качества и скорости

После запуска выполните на хосте с Python 3:

```bash
python3 scripts/benchmark.py
# Windows: py scripts/benchmark.py
```

Скрипт проверяет 20 размеченных товаров, время одиночного ответа и синхронную обработку 100 позиций. Пороги: точность top-1 ≥ 85%, одиночный ответ < 5 секунд, 100 товаров < 120 секунд. Для сохранения отчёта:

```bash
python3 scripts/benchmark.py --output benchmark-report.json
```

Замеры зависят от процессора. Первый запрос после старта может быть медленнее; readiness API включается после загрузки модели и индексации.

## Локальная разработка без Docker

Потребуются Python 3.12, Node.js 22+, PostgreSQL 16 с расширением pgvector и Redis 7.

```bash
# Backend
cd backend
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
export DATABASE_URL='postgresql+psycopg://procurement:password@localhost:5432/procurement'
export REDIS_URL='redis://localhost:6379/0'
uvicorn app.main:app --reload

# Worker — в отдельном терминале из backend/
celery -A app.tasks.celery_app worker --loglevel=INFO --concurrency=1

# Frontend — в отдельном терминале из корня
npm ci --legacy-peer-deps
npm run dev
```

Интерфейс разработки: http://localhost:3000; Vite проксирует `/api` на порт 8000. Для Docker frontend собирается на Debian-based `node:22-bookworm-slim`, не на Alpine: это обход npm-сбоя `Exit handler never called`, воспроизводимого в Node 22 + Alpine.

## Соответствие критериям кейса ТПУ

Текущая реализация покрывает основной сценарий классификации товаров по ПП РФ № 1875. При этом приёмка по точности и времени считается подтверждённой только после запуска `scripts/benchmark.py` на целевой машине. Встроенная проверка содержит 20 тестовых примеров. Фактическая точность ≥85%, время одиночного ответа <5 секунд и скорость 100 товаров <120 секунд считаются пройденными только после запуска benchmark на целевой машине.

Добавлен асинхронный приём и извлечение текста из PDF/DOCX через Celery/Redis с общим хранилищем для API и worker. PDF обрабатывается по страницам без удержания HTTP-запроса; DOCX обрабатывается с оценкой объёма, поскольку фиксированной пагинации в DOCX нет. Проверка обработки PDF на 60 страниц включена в backend-тесты. Для сканированных PDF без текстового слоя потребуется OCR; в текущей версии такие файлы явно помечаются как требующие распознавания.

Каждый результат содержит ссылку на уникальную локальную карточку по приложению и номеру позиции, а также внешний источник соответствующего приложения. Локальный переход прокручивает третью вкладку к конкретной строке и сохраняет адрес-якорь в URL. Внешний источник открывает приложение целиком: номер позиции явно указан в карточке, поскольку внешние правовые сайты не предоставляют стабильный универсальный URL-якорь для каждой строки таблицы.

Подробная матрица «критерий / реализация / статус / что осталось проверить» находится в `CASE_AUDIT.md`.

## Устранение неполадок

- **Порт занят:** освободите 8080/8000 или измените левую часть портов в `docker-compose.yml`, например `"8081:80"`.
- **API долго не готов:** проверьте `docker compose logs api`; первичная векторизация справочника выполняется один раз и сохраняется в PostgreSQL.
- **Пакет остаётся в очереди:** проверьте `docker compose ps` и `docker compose logs worker redis`.
- **Нехватка памяти:** закройте ресурсоёмкие приложения и увеличьте лимит памяти Docker Desktop.
- **Модель не скачивается при сборке:** проверьте доступ к Hugging Face. После успешной сборки контейнеры работают с моделью офлайн.
- **Обновление JSON отклонено:** сверьте обязательные поля и уникальность `id` с `backend/data/catalog.json`; приложение № 3 требует `quota_percent`.

Ссылки в позициях ведут на соответствующее приложение в правовой справочной системе; локальная карточка содержит номер позиции и код ОКПД2. Дата получения встроенного набора — 2026-10-30. Перед реальной закупкой сверяйте действующую редакцию НПА.

- Исправлен startup-crash FastAPI: добавлен именованный logger до startup lifespan. Ранее отсутствие `logger` вызывало `NameError`, API завершался с кодом 3 и frontend получал 502.
- Добавлен регрессионный тест, проверяющий, что logger объявлен до startup-hook.
- Обновлён интерфейс без смены цветовой системы: чёрный, белый, красный и нейтральные серые оттенки; глобальный шрифт — Times New Roman.
- Добавлены декоративные элементы, интерактивные состояния, адаптивные размеры и поддержка `prefers-reduced-motion`.

После обновления выполните `docker-compose up --build`. Проверка готовности API: `http://localhost:8000/api/v1/ready`. Если `api` не становится `healthy`, смотрите `docker-compose logs --tail=150 api`. Не удаляйте volume БД командой `docker-compose down -v`, если требуется сохранить локальный справочник.

### Исправление рассинхронизации пароля PostgreSQL

Если API сообщает `password authentication failed`, не удаляйте volume. Запустите `powershell -ExecutionPolicy Bypass -File .\fix-db-password.ps1` из корня проекта. Скрипт применит `POSTGRES_PASSWORD` из `.env` к существующей роли PostgreSQL и перезапустит API/worker/web без потери данных. Подробности — `DB_PASSWORD_FIX.md`.


## Персональные настройки проверяющего

Проверяющий копирует `.env.example` в `.env` и вводит собственные `POSTGRES_USER`, `POSTGRES_DB` и `POSTGRES_PASSWORD`. Один и тот же набор переменных используется PostgreSQL, API и Celery Worker. SQLAlchemy строит URL через `URL.create`, поэтому пароль со специальными символами корректно экранируется. `.env` не включается в репозиторий или релизный архив.

На чистом Docker volume пароль и пользователь создаются автоматически при первом запуске. Скрипт `fix-db-password.ps1` — исключительно инструмент для обновления пароля в уже существующем локальном volume разработчика; проверяющим он не требуется.

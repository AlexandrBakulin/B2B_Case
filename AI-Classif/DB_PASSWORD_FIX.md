# Смена пароля в уже существующей локальной базе разработчика

Этот документ нужен только если PostgreSQL уже был инициализирован с одним паролем, а разработчик позднее поменял `POSTGRES_PASSWORD` в `.env`. Для проверяющего на чистом развёртывании скрипт не нужен: PostgreSQL создаст роль автоматически при первом запуске с его собственным `.env`.

Изменение переменных окружения не изменяет пароль роли внутри уже существующего volume. Для существующей базы можно использовать `fix-db-password.ps1`, который обновит роль без удаления тома. Сначала сделайте резервную копию важных данных. Никогда не используйте `docker compose down -v`, если хотите сохранить базу.


Ошибка `FATAL: password authentication failed for user "procurement"` означает, что пароль уже существующей роли PostgreSQL не совпадает с `POSTGRES_PASSWORD` из текущего `.env`.

Это часто случается, если `.env` меняли после первого запуска PostgreSQL. Переменные `POSTGRES_USER`, `POSTGRES_PASSWORD` и `POSTGRES_DB` применяются образом PostgreSQL только при первоначальной инициализации пустого каталога данных. Изменение `.env` само по себе не меняет пароль роли в уже созданном томе.

## Безопасное исправление на Windows

1. Убедись, что в корне проекта есть `.env` и в нём заданы `POSTGRES_USER`, `POSTGRES_DB`, `POSTGRES_PASSWORD`.
2. Замени `docker-compose.yml` файлом из этого комплекта. В нём явно опубликован API-порт `8000:8000`.
3. Открой PowerShell в корне проекта `F:\AI-Classificator`.
4. Запусти:

```powershell
powershell -ExecutionPolicy Bypass -File .\fix-db-password.ps1
```

Скрипт читает пароль из `.env`, выполняет `ALTER ROLE` внутри контейнера PostgreSQL через локальное подключение и затем пересоздаёт только `api`, `worker` и `web`. Содержимое тома `pgdata` не удаляется.

## Проверка

```powershell
docker-compose port api 8000
docker-compose ps -a
docker-compose logs --tail=100 api
Invoke-RestMethod http://localhost:8000/api/v1/health
```

Ожидаемый результат для публикации порта — `0.0.0.0:8000` (или аналогичный адрес), для health endpoint — `status = ok`. Эндпоинт `/api/v1/ready` дополнительно ждёт загрузки модели и непустого каталога.

Не используй `docker-compose down -v` и не удаляй том `pgdata`: это удалит сохранённую базу данных.
